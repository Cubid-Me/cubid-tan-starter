# cubid-tan-starter

Canonical TanStack Start starter for the Cubid SDK. GitHub template; derived
projects add this repo as `upstream` and merge improvements.

## Stack and conventions

- TanStack Start 1.x on Vite with the generic Nitro adapter, React 19,
  Tailwind 4, pnpm, Vitest, ESLint (`@tanstack/eslint-config`) and Prettier
  (no semicolons, single quotes). Run `pnpm format` before committing.
- TanStack Start changes faster than most training data. Do not guess its API:
  run `npx @tanstack/cli doc start framework/react/guide/<page>` or
  `npx @tanstack/cli search-docs "<query>"` first.
- Server routes live in `src/routes/api/**` and must stay thin: they call
  handlers in `src/server/**` that take a Web `Request` and return a Web
  `Response`. Protocol and cookie logic lives in `src/lib/**`. Nothing under
  `src/server` or `src/lib` may import from `@tanstack/*`.
- Read env inside handlers (`process.env`), never at module scope. Browser-safe
  values use the `VITE_` prefix; server credentials never do.
- Path alias: `#/` maps to `src/`.
- `src/routeTree.gen.ts` is generated by `pnpm dev` or `pnpm build` and is
  committed. Do not edit it by hand.

## Cubid rules

- Keep dapp API keys, service-role keys, and recovery bundle material server
  side. The server demo returns a safe setup response when they are missing.
- Do not copy wallet-heavy or deprecated `@cubid/web2*` examples from the v1
  or v2 starters. Wallet examples are recovery-only.
- Redact tokens, codes, PKCE verifiers, nonce/state, cookies and PII in any
  visible trace or session output.

- `onAuthenticated` extras (`session.app`) are browser-visible and capped at
  1 KiB: ids and roles only. Cookie names come from
  `CUBID_SIWC_COOKIE_PREFIX`; derived apps set their own prefix.

## Workflow

- Node 22+ and pnpm 10 (`.nvmrc`, `packageManager`). CI runs
  `pnpm check`, `lint`, `typecheck`, `test`, `build` on Node 22 and 24.
- Record each task in `agent-context/session-log/` before committing.
- Validate with `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`.
  Protocol tests run against `src/test/fake-issuer.ts` with signed tokens;
  passkey sign-in is validated by hand and recorded in
  `agent-context/hosted-validation.md`, never claimed from the test suite.
